# ADR-0012 · MCP server design

**Status:** proposed (spike S1-13, re-checked at S4). Stateless per-request MCP handler on Fastify; tools generated from the core registry (`exposeTo ∋ mcp`), so MCP runs the same `execute()` as the screens (Q-28). Auth: PATs in S2; OAuth 2.1 via `oidc-provider` (CIMD + pre-registered Cowork client, no open DCR) in S4. High-risk approvals return `DECIDE_IN_APP` (INV-19). Reads and writes are audited with the MCP client name (implemented in S1 kernel).
