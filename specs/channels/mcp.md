# channels/mcp — Claude Code and Cowork access (the `/mcp` server; personal access tokens)

**Status:** signed with defaults · **Sprint:** S2 (OAuth in S4: see `specs/channels/mcp-oauth.md`, which also governs scopes, the `mcp.writes` flag and approvals over MCP) · **Quotation refs:** Q-27, Q-28, Q-29 · **Invariants:** INV-19

## Rules

| ID     | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Error code              |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------- |
| MCP-01 | `/mcp` speaks MCP over streamable HTTP, stateless per request. Tools are generated from the registry: every op with `exposeTo ∋ mcp`, named `<resource>_<action>` (the two-step approval tools are `prepare_decide_approval` / `confirm_decide_approval`, and `approval.decide` is not a tool, MCP-OA-14), with a JSON schema from its zod input.                                                                                                      | —                       |
| MCP-02 | Requests authenticate with an OAuth access token (MCP-OA-*) or a personal access token (`Authorization: Bearer dq_pat_…`, for headless use). Missing/invalid/expired/revoked → HTTP 401 with `WWW-Authenticate: Bearer …` naming the protected-resource metadata (MCP-OA-02).                                                                                                                                                                          | —                       |
| MCP-03 | Tokens are shown once, stored as SHA-256, expire in ≤ 30 days, can be revoked, and record last use. They are issued only from a signed-in web session (TOTP-verified for the roles that require it, as every web call is).                                                                                                                                                                                                                             | `VALIDATION`            |
| MCP-04 | Token scopes: `read` (queries) and `write` (commands; also the two-step approval tools for a PAT). Privileged roles (ceo, director, ops_lead, finance, admin) can only get `read` tokens, and a write token acts read-only once its owner holds a privileged role; changing someone's roles revokes their tokens. At most 5 active tokens per person. A write tool with a read token is refused. Commands also need the `mcp.writes` flag (MCP-OA-13). | `FORBIDDEN`, `CONFLICT` |
| MCP-05 | Every tool call runs through `execute()` with channel `mcp` — the same permissions, gates and audit as the screens — and is audited by the user's name with the token's client label.                                                                                                                                                                                                                                                                  | —                       |
| MCP-06 | Domain errors come back as tool errors (`isError: true`) with the stable code and the message in the user's language — never a stack trace.                                                                                                                                                                                                                                                                                                            | —                       |
| MCP-07 | 60 calls per minute per token (per person for OAuth, MCP-OA-12); over that → HTTP 429 with `Retry-After`.                                                                                                                                                                                                                                                                                                                                              | `RATE_LIMITED`          |
